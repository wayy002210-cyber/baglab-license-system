# 0.4.4 文案页面跨进程修复验收记录

## 真实根因

百炼 Key、`deepseek-v3` 和后端接口均可正常调用。故障发生在 Electron 的
Renderer 与 Preload 隔离边界：

1. 文案页面把 Vue 响应式人设对象中的 `brandFacts` 数组直接传给
   `window.autocut.generateTopics`。
2. Electron 无法结构化克隆 Vue Proxy，请求在到达百炼之前即抛出
   `An object could not be cloned`。
3. 第一层修复后，选题已经能够显示；但随后保存创作草稿时又把整个响应式
   草稿传给 Electron，再次触发同一个克隆错误，因此页面仍误报生成失败。

此前直接 API 验收使用普通 JavaScript 对象，绕过了 Vue 响应式页面和草稿
保存步骤，所以不能复现该问题。

## 修复

- 新增文案请求转换层，把 `brandFacts` 和 `bannedWords` 显式复制为普通数组。
- 草稿跨进程保存前使用共享 Zod Schema 生成经过校验的普通对象。
- 同时覆盖选题生成和完整文案生成，避免进入下一步后出现同类错误。
- 增加响应式嵌套数组的结构化克隆回归测试。
- 增加响应式创作草稿的跨进程保存回归测试。

## 打包版真实验收

- 使用用户现有百炼 Key、`deepseek-v3` 和现有人设。
- 从文案页面真实点击“生成选题”。
- 页面显示“操作已完成”，进度为 100%。
- 页面显示五个有效选题。
- 关闭打包程序并重新启动后，五个选题仍然存在。
- 全程未出现 Renderer 控制台错误。
