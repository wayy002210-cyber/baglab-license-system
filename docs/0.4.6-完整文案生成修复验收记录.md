# 0.4.6 完整文案生成修复验收记录

## 故障根因

选题接口与完整文案接口均已成功调用百炼 DeepSeek。完整文案失败发生在模型响应之后：

- 当前人设禁用词包含“第一”和单字“最”。
- 部分选题生成的文案连续三次仍包含“最”。
- 旧逻辑会丢弃整篇文案并返回通用错误。
- 页面只短暂显示消息浮层，没有保留完整文案阶段的进度和错误详情。

## 修复

- 文案命中禁用词时自动携带具体命中词重试，最多三次。
- 三次后仍命中时不再丢弃文案，保留草稿供后续“AI 违禁词检查”处理。
- 字数或 JSON 结构不合法仍属于阻断性错误。
- 完整文案生成阶段增加固定进度、失败原因和重试入口。
- 增加稳定的 `data-action="generate-copywriting"` 界面测试定位。

## 验证

- 当前真实人设、真实百炼密钥、DeepSeek 模型直接生成完整文案成功。
- 0.4.6 打包程序内实际点击“生成完整文案”成功，界面写入 270 字，重读数据库草稿仍为 270 字。
- 后端覆盖“首次命中后修复成功”和“连续三次命中但保留草稿”。
- 全量 Vue、Electron、Python 自动测试及生产构建通过。
