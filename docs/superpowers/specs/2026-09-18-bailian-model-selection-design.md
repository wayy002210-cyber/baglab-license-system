# 百炼文案模型选择与手动更新设计

## 目标

在不改变选题/文案全局去重、MiniMax、混剪、发布及平台适配逻辑的前提下，为百炼文案生成增加可选择模型和用户主动触发的模型更新能力，并淘汰已失效的 `deepseek-v3` 默认配置。

## 范围

本次仅包含：

- 百炼文本模型列表查询、筛选和可用性验证。
- 设置页的文案模型选择、“点击查看模型更新”按钮、状态和错误展示。
- 旧 `deepseek-v3` 配置迁移。
- DeepSeek V4 系列结构化输出兼容。
- 与上述行为直接相关的自动测试、Build ID、安装包和哈希。

明确不包含：

- 不提供去重开关或去重强度选择。现有选题和文案去重继续全局强制执行。
- 不修改 MiniMax 模型、音色或音频生成流程。
- 不修改混剪、自动发布、平台适配、素材和客户项目数据。
- 不后台定时刷新模型，不在启动时访问百炼模型列表。

## 用户交互

设置页现有“AI 服务密钥”区域保留，在百炼配置中增加：

- 当前文案模型下拉框。
- “点击查看模型更新”按钮。
- 最近一次成功检查时间。
- 最多五个推荐模型及状态说明。

初始进入设置页时只读取本地缓存，不发起网络请求。用户点击更新按钮后才查询并验证模型。更新成功只更新候选列表，不自动切换当前模型；用户明确选择并保存后才改变选题和文案生成所用模型。

如果当前保存的是已下线的 `deepseek-v3`，读取设置时迁移为 `deepseek-v4.1-flash`。迁移不修改 API Key、历史文案或其他设置。

## 模型发现与推荐

Electron 从 Windows 凭据管理器读取百炼 API Key，通过本地 FastAPI 调用模型发现服务。密钥不进入 Vue、不写入数据库或日志。

服务端在用户点击更新时执行：

1. 请求百炼模型列表接口。
2. 只保留文本生成、兼容当前 Chat Completions 调用且适合结构化内容生成的模型。
3. 按固定优先级对当前模型结果排序：
   - `deepseek-v4.1-flash`
   - `qwen3.7-plus`
   - `qwen3.8-flash`
   - `deepseek-v4-pro`
   - `qwen3.8-max`
4. 对候选模型发起最小生成请求，验证当前 API Key 是否真的可调用。
5. 最多返回五个通过验证的推荐模型。

模型列表接口不可用时，可使用同一组推荐候选继续做实际调用验证，但必须在结果中标注“列表服务降级”。不能把未经验证的模型标记为可用。

本地仅缓存模型 ID、显示名称、可用状态、说明和检查时间。缓存不包含密钥，且不会自行刷新。

## 生成调用兼容

保存的文案模型继续同时用于选题生成和文案生成。热点检索仍使用现有固定检索模型，不随文案模型切换。

对于默认开启思考模式且需要结构化 JSON 输出的 DeepSeek V4 系列，请求显式关闭思考模式，继续使用现有 `response_format=json_object` 和结构校验。普通文本生成不增加无关参数。

## 错误处理

- 未配置 Key：提示先保存百炼 API Key。
- 401：提示密钥无效或地域不匹配。
- 403：显示模型无权限、服务未开通或额度限制，并保留服务端错误码。
- 429：提示请求过于频繁。
- 网络错误：提示网络连接异常，保留旧缓存和当前模型。
- 模型列表成功但不足五个：只显示实际验证可用的数量。
- 当前模型在刷新后不可用：保留显示并标记不可用，要求用户选择可用模型后才能保存；不静默替换。

任何失败都不得清除已保存的 Key、客户项目、素材、文案历史或去重记录。

## 数据与接口

扩展现有文案模型设置，保存：

- `defaultModel`
- `temperature`
- `candidateModels`
- `modelRecommendations`
- `modelsCheckedAt`

新增一个受本地会话令牌和桌面授权证明保护的模型发现接口，以及对应 Electron IPC。接口只返回脱敏模型元数据和统一错误代码。

## 测试与交付

自动测试至少覆盖：

- `deepseek-v3` 向 `deepseek-v4.1-flash` 迁移。
- 不点击按钮时不发起模型列表请求。
- 手动刷新最多返回五个已验证模型。
- 无权限、下线、网络失败和列表降级。
- DeepSeek V4 结构化生成关闭思考模式。
- 用户选择模型后，选题与文案使用该模型。
- 去重逻辑始终启用，且本次变更不改变现有去重测试结果。
- MiniMax、混剪和发布相关既有测试不回归。

完成类型检查、Vitest、pytest、生产构建和秘密扫描后，递增 Build ID 并生成新的 Windows 安装包。保留旧安装包，不覆盖既有成果；记录新安装包、`app.asar` 和后端 EXE 的 SHA-256。
