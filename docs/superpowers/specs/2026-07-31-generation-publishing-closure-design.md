# 成片、字幕标题与发布闭环修复设计

## 目标

修复任务排队时错误显示 75%、事件连接中断误报失败、取消后留下不可播放 MP4、发布窗口闪退、排期英文和字幕标题配置不完整等问题，并让任务进度至少每 5 秒提供一次可解释反馈。

## 任务状态与成片生命周期

- 在合成完成后先进入“等待编码器”，显示排队位置和等待时长；只有取得全局编码权后才进入“编码成片”。
- 阶段变化立即推送；等待和编码阶段最多每 5 秒推送并持久化一次进度或心跳。
- 编码进度来自 FFmpeg 的媒体时间，不使用虚假定时增长。没有新帧时仍推送“编码器仍在工作”的心跳和已耗时。
- 桌面端事件流断开后查询任务真实状态并重连，不把监听连接异常直接写成任务失败。
- 后端使用跨进程 Windows 文件锁保证整台机器只运行一个编码任务，避免残留后端绕过进程内锁。
- FFmpeg 输出写入同目录唯一 `.partial.mp4`。成功退出后使用 ffprobe 校验容器、H.264 视频、AAC 音频和有效时长，再原子替换最终文件。
- 取消、失败、超时会终止进程树并删除临时产物。正式输出只代表已验证的可播放成片。

## 字幕、标题与样式模板

- 字幕和顶部标题样式增加 `positionX`、`positionY`，坐标基于 1080×1920 画布。
- ASS 生成器使用 `\pos(x,y)` 精确定位，同时保留旧任务的 alignment/marginV 兼容逻辑。
- 新增可命名的“字幕与标题样式模板”，整体保存两套字体、颜色、描边、阴影、字号和坐标；支持应用和删除。
- 文案生成结果增加 5–6 个汉字的 `mainTitle`。模型格式异常时从选题提取核心短语作为确定性兜底。
- 标题进入创作草稿、任务快照、预览和最终 ASS，任务创建后保持不可变。

## 本机字体

- 合并读取 Windows 系统字体注册表、当前用户字体注册表、`C:\Windows\Fonts` 和 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`。
- 支持 `.ttf`、`.otf`、`.ttc`、`.otc`，解析集合字体中的每个 family/name，并按字体族与文件路径去重。
- 无法解析或权限不足的字体被跳过并记录诊断，不阻断页面。

## 排期与发布

- Element Plus 全局使用简体中文 locale，日期控件和月份、星期、确认按钮全部中文化。
- canceled/failed 记录允许删除；执行中的任务只能取消，避免删除仍在运行的发布。
- 修复被错误编码的中文页面选择器。抖音发布器按可访问名称、placeholder、contenteditable 和页面文本多级定位。
- 发布前再次校验视频可播放。
- 登录失效、验证码、页面结构变化或找不到控件时返回 `needs_user`，保留浏览器窗口一段人工接管时间，保存脱敏截图、URL 和中文错误，不误报发布成功。

## 验收

- 两条及以上任务同时创建时只有一条显示“编码成片”，其余显示“等待编码器”。
- 等待和编码期间 UI 每 5 秒内得到进度或心跳反馈。
- 取消任务后不存在正式 MP4 或遗留 `.partial.mp4`；失败文件不会出现在可发布列表。
- 完成文件通过 ffprobe，系统播放器可打开。
- 字幕和标题 X/Y 坐标生效，样式模板重启后仍可复用。
- AI 标题为 5–6 个汉字并进入最终视频。
- 排期控件全中文，已取消记录可删除。
- 抖音页面变化时进入人工接管并保留窗口，不再闪退。
