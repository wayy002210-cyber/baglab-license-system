# 袋研官生产闭环 V2 重构设计

## 目标与范围

本轮不再补空壳页面，而是把现有功能重构成可恢复、可诊断、可验收的本地生产状态机。固定主流程为：

`人设档案 → 文案生成 → 音频制作 → 镜头剪辑 → 创建任务 → 成片 → 抖音/视频号发布`

发布平台仅保留抖音和视频号，移除小红书。参考软件仅用于验证通用交互、模块边界和运行时组织，不复制其品牌、素材或专有代码。

## 已确认故障

1. Windows 凭据库中已有百炼密钥，但实际请求返回 `401 invalid_api_key`。
2. DeepSeek 通过百炼调用时被统一附加结构化输出参数；不支持该能力的模型会失败。
3. 草稿自动保存采用无错误处理的异步调用，保存失败会表现为按钮无反应。
4. 音频页面按段落生成，但缺少明确的“整篇生成—试听—确认”状态闭环。
5. 镜头模板和当前创作草稿混用，“保存镜头方案”语义不清，脚本结构化改写没有独立能力。
6. 发布账号创建与长时间登录等待绑定在一次请求中，失败缺少阶段日志，浏览器会话生命周期不稳定。
7. 当前平台领域类型仍包含小红书，尚未实现视频号适配器。

## 领域状态机

### 创作草稿

草稿增加明确阶段和版本：

- `persona`
- `copywriting`
- `audio_configured`
- `audio_generating`
- `audio_ready`
- `editing`
- `ready_for_task`

每次阶段迁移必须先通过 Zod 校验并持久化。界面展示 `未保存 / 保存中 / 已保存 / 保存失败`。自动保存失败必须显示中文错误，用户可重试；路由跳转只在保存成功后发生。

### 长耗时操作

文案、配音、合成、账号登录、发布统一使用：

- `idle`
- `validating`
- `queued`
- `running`
- `success`
- `failed`
- `needs_user`
- `canceled`

远程接口没有真实进度时使用阶段式进度，不伪造精确百分比。失败数据包括错误码、中文说明、建议操作、是否可重试和诊断 ID。

## 百炼与 DeepSeek

系统设置增加“测试百炼连接”。保存密钥后立即执行最小请求并显示：

- 密钥有效
- 密钥无效
- 模型不存在或无权限
- 限流
- 网络/超时
- 返回格式异常

模型配置维护能力表。DeepSeek 默认不发送 `response_format`，由提示词要求返回 JSON，再执行容错提取、Schema 校验和最多两次格式修复。支持结构化输出的模型才附加结构化参数。

文案接口包括：

- 生成五个选题
- 根据选题生成 200–1000 字口播稿
- 保留原脚本段落职能和论证顺序进行结构化改写
- 违禁词检查与建议替换

“一键改写”产生新的文案变体，不覆盖模板定义。批量任务以原文、结构、种子和改写结果形成不可变快照。

## 音频制作

声音模型移入系统设置。音频页只保留创作需要的参数：

- 音色
- 情感
- 语速
- 音调
- 声音克隆

人声音量从音频页移到镜头剪辑的统一混音区，与 BGM 音量并排调整。

页面顶部是整篇音频工作台：确认生成、真实段落进度、当前阶段、整体播放/暂停/重播、时间轴和重新生成。下方音色以卡片展示。试听规则：

- 任意时刻只能播放一个音频。
- 点击试听总是从头开始。
- 再次点击当前卡片停止。
- 播放中卡片具有明确高亮与动画状态。
- 切换卡片会停止上一个音频。

整篇配音仍按段缓存和重试，全部成功后合并为可连续试听的预览音频。参数变化只使受影响缓存失效。生成成功且整体试听可用后才能进入镜头剪辑。

## 镜头剪辑与模板

左栏是模板库；模板定义结构，不保存当前任务产物。模板操作为新建、编辑、复制、应用、另存和删除。

中栏是当前草稿镜头：

- 从文案按自然段或标点重新拆分
- 一键结构化改写
- 添加、删除、排序镜头
- 每镜头选择素材分类
- 编辑口播、时长策略和原声静音
- 显示对应音频状态

右栏是预览与媒体设置：

- 9:16 大尺寸预览
- 本机字体下拉和实时字体预览
- 标题/字幕样式
- BGM 单曲或文件夹
- 人声音量与 BGM 音量并排混音

“保存镜头方案”取消，替换为“保存为模板”和“保存当前创作”。最终按钮为“创建混剪任务”，校验文案、音频、素材分类、字体和输出目录后生成不可变任务快照。

## 发布账号与排期

平台类型调整为：

```ts
type PublishPlatform = "douyin" | "wechat_channels";
```

创建账号只保存名称、备注、平台和独立浏览器目录。账号卡片提供“打开登录窗口”，后台启动长生命周期 persistent context，前端轮询状态。关闭软件或用户关闭浏览器时正确释放资源，登录 Cookie 仅保存在对应本地目录。

平台适配器：

- 抖音：抖音创作者中心。
- 视频号：视频号助手。

登录、验证码和风控由用户接管。发布适配器负责上传视频、填写标题/话题、选择平台支持的发布时间并提交。每个关键步骤记录脱敏日志和失败截图。同一账号串行执行；任务使用幂等键避免重复提交。

排期优先使用平台页面提供的定时发布能力。若平台当时不提供或账号无权限，任务进入 `needs_user`，不得伪报成功。

## 可观测性与安全

- Electron、Python和逐任务日志统一诊断 ID。
- 所有 IPC/HTTP 错误映射为中文可执行提示。
- API Key、Cookie、Authorization和浏览器存储内容不得进入日志或诊断包。
- 设置页提供百炼、MiniMax、本地浏览器运行时和 FFmpeg 的独立健康检查。
- 真实外部登录和风控验收集中保留给用户最后操作。

## 验收标准

1. 无效百炼密钥明确显示 401 对应的中文处理方式；有效密钥可完成选题、文案和改写。
2. 自定义 200–1000 字文案保存后可靠进入音频页，重启后恢复。
3. 音色卡片互斥播放，整篇配音有生成进度、成功提示、时间轴和重播。
4. 模板可完整编辑，当前文案可拆镜头和一键结构化改写，素材分类可用。
5. 人声与 BGM 在同一混音区调整，成片响度关系可验证。
6. 抖音和视频号账号卡片能启动独立登录浏览器并恢复登录态。
7. 发布排期不会重复提交；失败能定位具体平台步骤。
8. 全量 Vitest、Pytest、类型检查和构建通过，并生成可安装的 Windows 成品。
