# 选题与文案去重、结构多样性及热点融合设计

日期：2026-09-15

状态：待用户确认

实施路线：方案 B（本地历史库＋多层判重＋结构轮换＋热点检索）

## 1. 目标

在不改动授权、混剪、发布和平台适配逻辑的前提下，改造现有 AI 选题与口播稿生成链路，使系统具备以下能力：

- 每次展示的五个选题在问题、受众、场景、论点、证据和表达结构上有实质差异。
- 已展示、已选择、已生成、已归档或已发布的内容均参与后续去重。
- 同义改标题、复用相同开场、复用相同论证顺序不能绕过去重。
- 同一大论点近期不重复；冷却期后只有在多个内容维度发生实质变化时才能重新使用。
- 文案结构和开场方式按历史使用情况轮换，不固定使用单一模板。
- 每批选题尝试包含一至两个有来源、与业务相关的近期热点选题。
- 搜索失败或没有合适热点时生成常规选题，不虚构新闻或事实。
- 判重后不足五个时继续定向补充；达到重试上限仍不足时明确失败，不使用重复题凑数。

本设计中的“不重复”是一项强制交付策略：被系统判定为重复的候选不会展示。中文语义空间无法数学证明永久绝对唯一，因此系统使用多层检测、历史记录和模糊区模型裁决共同降低漏判。

## 2. 当前问题

当前 `backend/app/copywriting/topic_service.py` 只检查同一批五个短标题是否完全相同，不读取历史内容，也不检测描述、开场、论点或脚本结构。提示词中的“同行低价真相”示例还会持续诱导模型生成低价与质量话题。

当前 `src/renderer/views/CopywritingView.vue` 只有在用户生成文案时才创建文案项目。仅展示后被换掉的题目不会保存，因此后续可再次出现。

当前 `electron/repositories/copywriting-project-repository.ts` 保存生成后的标题、选题描述和正文，但归档记录最多保留三十条，删除项目会丢失可用于判重的信息。

参考脚本检索会反复传递最相关的三篇完整正文，容易造成相同语序、开场和结构持续复用。

百炼调用目前固定 `temperature=0.4`，没有结构策略、历史约束或联网搜索参数。

## 3. 总体架构

生成链路分为六个独立组件：

1. 内容历史仓库：持久保存选题、文案和结构指纹。
2. 内容规划器：根据人设、内容矩阵和近期使用情况生成候选蓝图。
3. 判重器：执行精确、文字、内容身份和语义四层判断。
4. 多样性选择器：从合格候选中选出差异最大的五个。
5. 热点提供器：按需联网检索、校验、缓存可用热点。
6. 文案生成器：根据选题蓝图选择低频结构，生成并复检脚本。

数据流：

```text
人设、品牌事实、参考结构、历史摘要、热点资料
                    ↓
             生成 12～15 个蓝图
                    ↓
        规范化 → 多层判重 → 多样性评分
                    ↓
          不足五个时按缺失维度补充
                    ↓
          保存“已展示”记录并返回五题
                    ↓
        选中题目＋低频结构 → 生成文案
                    ↓
           文案判重与事实约束检查
                    ↓
              通过后保存正文历史
```

## 4. 数据模型

### 4.1 `content_history`

新增不可因项目删除而级联删除的历史表：

- `id`
- `persona_id`
- `content_type`：`topic` 或 `script`
- `lifecycle_state`：`shown`、`selected`、`generated`、`collected`、`archived`、`published`、`rejected`
- `project_id`：可为空，仅用于追溯
- `display_title`
- `short_title`
- `description`
- `hook`
- `content_text`
- `identity_json`
- `structure_type`
- `hotspot_json`
- `normalized_hash`
- `lexical_signature_json`
- `semantic_vector_json`：可为空
- `created_at`
- `last_used_at`

项目被删除时保留历史指纹。升级通过非破坏性 SQLite migration 新增表和索引，不迁移或删除现有客户数据。

### 4.2 内容身份 `identity_json`

每个候选必须包含：

- `audience`：目标受众
- `scenario`：具体使用或决策场景
- `problem`：要解决的问题
- `thesis`：核心结论
- `evidence_type`：工艺、对比、计算、公开事实、品牌已确认事实等
- `angle`：切入视角
- `structure_type`：表达结构
- `hook_type`：开场类型
- `viewer_gain`：观众得到的具体价值
- `hotspot_id`：可为空

该数据用于判断两个标题背后的内容是否实际相同，不直接展示给普通用户。

### 4.3 标题拆分

- `display_title`：建议 10～22 字，用于表达完整选题。
- `short_title`：保留 5～8 个中文字符，用于封面、文件名和下游兼容。

现有 `main_title` 继续承载短标题；新增完整标题字段或以兼容字段保存。老项目读取时自动以原短标题作为完整标题，不影响已有数据。

## 5. 判重规则

### 5.1 精确判重

标题、描述、开场和正文经过大小写、空白、标点、常见语气词和数字格式规范化后计算 SHA-256。哈希相同直接拒绝。

### 5.2 文字近似判重

使用中文字符 n-gram、关键词集合和连续短语重合度进行本批与历史比较。分别计算标题、开场、选题描述、文案前三句和全文的相似度。

阈值集中配置，不能散落在提示词中。初始值由回归样本调校，测试不依赖某个未经验证的固定经验数字。

### 5.3 内容身份判重

问题、论点、受众、场景、证据和结论基本相同，即使措辞不同仍拒绝。

近期出现过的同论点默认拒绝。超过冷却期后，只有受众、场景、证据、表达结构四项中至少三项发生实质变化，并且标题、开场与结尾均不复用，才允许再次使用。

冷却期作为设置项，首版默认九十天；永久精确重复不受冷却期影响，始终拒绝。

### 5.4 语义判重

使用现有百炼账号可调用的嵌入模型批量生成向量，向量保存在本地 SQLite，由 Python 计算余弦相似度，不引入本地大型模型或向量数据库。

若嵌入调用不可用，降级为字符 n-gram、关键词和内容身份判重。位于模糊区间的候选使用一次小型结构化模型裁决，返回 `duplicate`、相似历史 ID 和判断理由。裁决器只能收紧结果，不能放行已命中硬规则的候选。

### 5.5 历史范围

- 同一人设：完整严格历史。
- 不同人设但同一行业：用于降低公共题材重复，权重较低。
- 本批候选：最严格的相互差异要求。
- 已展示但未选择的题目：进入短期严格历史。
- 已生成或发布的题目和文案：进入长期历史。

## 6. 选题规划方法

规划器不再固定生成“避坑、标准、传播、工厂故事、指南”五类，而是从以下矩阵选择近期低频组合：

- 内容领域：材料、工艺、报价、打样、验收、采购、品牌、生产、使用、环保、消费心理、失败复盘、趋势。
- 受众：品牌负责人、采购、设计师、活动公司、电商卖家、门店经营者、消费者。
- 场景：展会、礼赠、零售、快闪、电商发货、员工用品、社区活动、日常使用等。
- 证据：工艺原理、步骤演示、正反对比、成本计算、公开来源、已确认品牌事实。
- 表达结构：反常识、流程揭示、问答、对比测试、决策复盘、成本账、误区纠正、现场观察、热点解释。

首轮生成 12～15 个紧凑蓝图。多样性选择器按“新颖度、相关性、可证明性、五题覆盖差异”评分。若不足五个，只将缺失的受众、场景或结构反馈给模型生成补充候选，最多三轮。

移除带有具体业务倾向的示例，改用只描述 JSON 字段的中性结构示例，避免“同行低价真相”继续污染结果。

## 7. 文案生成方法

文案提示词从单一要求改为“蓝图＋结构契约”：

- 每篇先选取近期低频的 `structure_type` 和 `hook_type`。
- 同一批脚本不得使用相同结构和相同开场套路。
- 参考脚本只提供结构摘要、节奏和语气特征，不直接传入完整正文供仿写。
- 事实只能来自人设已确认事实或带来源的热点资料。
- 禁止自动创造客户故事、销量、损失金额、排名、热搜、政策结论和工厂经历。
- 不强制所有脚本采用“三段式”“列五点”或“先说结论”。

结构池首版包含：反常识解释、现场切入、正反对比、层层问答、生产流程、成本计算、失败复盘、情境对话、测试演示、热点回应、误区纠正和决策记录。

生成后检查标题、前三句、主要论证顺序、连续短语、例证和结尾 CTA。硬重复直接重写；模糊相似只重写重复片段或更换整体结构。三次仍不能通过则保留失败记录并向用户说明，不能返回低质量重复稿。

## 8. 热点融合

热点提供器使用百炼联网搜索，检索范围限定为与包装袋、材料、零售、制造、品牌传播、环保和消费场景有关的近期内容。

普通模型调用继续走现有 OpenAI 兼容接口。热点查询优先使用 DashScope 能返回来源信息的协议，保存：

- 来源标题
- 原始链接
- 发布日期
- 检索时间
- 摘要
- 与当前人设的相关性说明

默认每批尝试加入一至两个热点题。只有来源有效、发布时间明确、与人设直接相关并能形成实际观点时才入选。没有合格热点时不强行插入。

热点检索使用短时缓存，首版默认六十分钟。同一热点不能在近期批次中反复换标题使用。网页内容按不可信外部输入处理：去除脚本和 HTML、限制长度，不允许其改变系统规则或读取本地信息。

联网失败、模型不支持搜索或返回来源不足时，页面显示“本次热点不可用”，但常规选题仍可继续生成。

## 9. 前端交互

选题卡片显示：

- 完整内容标题
- 封面短标题
- 具体论述方向
- 开场方向
- 内容角度标签
- 热点标识、来源和日期（如适用）

“换一批”生成的新候选会立即记录为已展示。增加简短状态提示，例如“已避开本地历史 126 条内容”。

不提供绕过硬判重的按钮。用户可选择常规、热点优先两种内容倾向，但两种模式都必须通过历史去重。

## 10. 错误处理与性能

- 历史比较只加载当前人设的紧凑指纹和最相似候选，不把全部正文放入模型上下文。
- 嵌入按批处理并缓存；相同文本不重复请求。
- 热点按查询和时间窗口缓存。
- 选题补充只生成缺失数量和缺失方向，控制 Token 消耗。
- 数据库写入使用事务，确保五个展示候选一起登记。
- 任一外部增强能力失败时，保留本地硬判重能力。
- 对用户区分显示：网络失败、模型输出无效、新鲜候选不足、热点来源不足和脚本重复未通过。

## 11. 兼容性与边界

- 不改变现有客户项目、素材、发布数据和授权记录。
- 历史表位于原有本地数据库，正常安装升级后保留。
- 本地历史无法自动覆盖另一台电脑；跨设备团队级去重留作未来云端同步能力。
- 不把文案或品牌资料上传到授权服务，也不复用授权数据库。
- 新增接口字段保持向后兼容，旧记录缺少新字段时使用安全默认值。

## 12. 测试与验收

自动测试至少包括：

1. 同批完全重复、同义标题和相同内容身份被拒绝。
2. 连续二十批、一百个展示题无精确重复标题或开场。
3. 已展示未选择的题目参与后续去重。
4. 删除、归档项目后历史指纹仍保留。
5. 同论点在冷却期内拒绝，冷却期外仍需满足多维变化规则。
6. 判重不足五题时定向补充，达到上限后明确失败。
7. 脚本前三句、结构、例证、连续短语和 CTA 重复时触发重写。
8. 参考脚本不会被大段复刻。
9. 热点题必须带来源、发布日期和检索时间。
10. 热点断网、超时、来源缺失时正确降级。
11. 虚构客户、数据、热搜或政策信息的输出不能通过验证。
12. SQLite migration 保留所有既有文案项目和用户数据。
13. 软件升级后历史记录仍可读取并继续判重。

除固定样本测试外，增加可重复的生成模拟和人工抽检报告。人工质量抽检重点核对“是否产生了新的观众价值”，不只核对字面相似度。

## 13. 实施边界与顺序

1. 先补数据库迁移和判重测试。
2. 实现内容历史仓库和历史摘要接口。
3. 实现内容身份、文字判重、语义判重与模糊区裁决。
4. 重构选题规划、候选补充和多样性选择。
5. 实现文案结构轮换和生成后复检。
6. 实现热点检索、来源解析和缓存。
7. 更新 Electron IPC、共享契约与 Vue 选题界面。
8. 运行单元、集成、迁移和连续生成测试。
9. 本地联调稳定后再决定是否制作新安装包。

本次修改限定在选题、文案及其必要的数据和界面链路，不重构无关模块。
