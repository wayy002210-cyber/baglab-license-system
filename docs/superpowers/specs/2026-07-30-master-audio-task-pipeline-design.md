# 单条主音频与任务流水线修复设计

## 目标

完整口播稿只调用一次 MiniMax，生成一条连续主音频。镜头拆分只负责素材选择、画面时长和字幕内容，不再触发逐镜头 TTS。修复背景音乐为空导致任务合成失败的问题，并用真实创作草稿跑通任务到成片。

## 数据设计

继续使用现有 `audioSegments` 字段以兼容数据库和已安装用户数据，但新流程只保存一个元素：

- `id` 固定为当前文案和声音参数共同决定的稳定 ID。
- `text` 保存完整口播稿。
- `audioPath` 保存整篇配音文件。
- `durationSec` 保存整条音频时长。
- `sourceStart/sourceEnd` 覆盖完整文案范围。
- `status` 表示整篇配音的唯一生成状态。

旧草稿中存在多段音频时，进入音频页面后按当前完整文案重建为一个待生成主音频，不拼接旧分段，避免把旧架构继续带入任务。

## 音频页面

- 选择音色、情感、语速、音调后，点击一次“生成整篇配音”。
- MiniMax 只接收一次完整脚本文本。
- 页面只显示一个生成进度、一个主播放器和重新生成按钮。
- 参数或文案变化后，已生成主音频变为待重新生成。
- 成功后才能进入镜头剪辑。
- 音色卡片试听仍是独立短文本试听，不属于成片配音。

## 镜头与时间分配

镜头文本继续按段落和句子拆分，用于匹配素材与字幕。镜头时长不再来自各自音频文件，而由主音频总时长分配：

1. 对每个镜头统计去除空白后的字符数。
2. 按字符数占比分配主音频总时长。
3. 每镜头设置最小可用时长，避免极短镜头。
4. 最后一个镜头吸收浮点余差，保证所有镜头时长之和严格等于主音频时长。

首版不依赖 MiniMax 字级时间戳。字幕按镜头时间段展示，后续若接入可靠时间戳，可替换分配器而不改主音频模型。

## 任务流水线

- 工作流创建的任务快照携带唯一主音频。
- `generate_voice` 检测到有效主音频后直接复用，不调用 MiniMax。
- 没有主音频的旧任务允许以完整脚本补生成一次，不能逐镜头生成。
- `compose` 只创建一条从 `0` 秒开始的主声音轨。
- 视频镜头和字幕使用分配后的镜头时长。
- `bgm` 为 `null` 时按未配置处理，使用默认背景音量，不调用空值的 `.get()`。
- 任务错误必须带阶段名称和中文原因，界面不直接显示 Python 原始异常。

## 兼容与恢复

- 数据库版本不升级，沿用 `audioSegments` 数组结构。
- 已失败任务重试时继续读取不可变快照；旧快照多段音频可作为兼容输入，但新任务只创建单条主音频快照。
- 已完成视频和旧音频文件不删除。

## 测试与验收

- 单元测试证明完整文案只调用一次 TTS。
- 单元测试证明主音频总时长按镜头文字权重分配，且总和无误差。
- 单元测试证明 `bgm=null` 可正常构建项目。
- 渲染层测试证明音频页面只生成并保存一个主音频元素。
- 流水线测试证明已存在主音频时 MiniMax 调用次数为零，合成项目只有一条人声音轨。
- 使用当前真实草稿重新生成整篇配音，创建任务并运行至可播放 MP4。
- 成片检查人声连续、无段落拼接断裂，视频总时长与主音频一致。
