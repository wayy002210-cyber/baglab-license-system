# 袋研官内容、音频与镜头创作工作流设计

## 1. 目标

在现有 Windows 本地混剪工作台上补齐从人设到成片的核心创作链路，并统一袋研官品牌视觉。正式生产顺序为：

`人设档案 → 文案生成 → 音频制作 → 镜头剪辑 → 创建任务`

侧边栏是唯一的全局导航。页面可以提供“上一步”“下一步”操作，但不再增加顶部步骤条，避免两套导航产生冲突。

## 2. 信息架构

侧边栏按以下顺序展示：

1. 工作台
2. 人设档案
3. 素材中心
4. 文案生成
5. 音频制作
6. 镜头剪辑
7. 任务中心
8. 发布账号
9. 发布排期
10. 系统设置

素材中心是创作前置资源，不进入线性草稿步骤。用户可以通过侧边栏随时维护素材；镜头剪辑读取素材中心的分类和健康状态。

## 3. 创作草稿

系统新增一个本地创作草稿，串联各创作页面。草稿自动保存并在应用重启后恢复，包含：

- 当前 Persona。
- 当前文案模型、生成参数、候选选题、已选选题和完整文案。
- 文案检查结果及用户确认的替换。
- 音色来源、MiniMax 音色 ID、克隆任务、情感、语速、音量、音调。
- 文案分段、逐段音频路径、音频时长和生成状态。
- 镜头顺序、素材分类、时长、原声开关和素材降级策略。
- BGM 来源、选择模式、音量。
- 标题、字幕样式和画布设置。

创建任务时将草稿转换成不可变任务快照。后续修改人设、模板或系统默认设置不得改变已创建任务。

成功创建任务后，用户可以清空草稿，或复制草稿继续批量创作。

## 4. 文案生成

### 4.1 模型配置

文案服务继续使用百炼 OpenAI-compatible 接口，并增加模型选择：

- 系统设置保存默认模型。
- 单次创作允许覆盖默认模型。
- 支持百炼可用的通义模型和 DeepSeek 模型。
- 任务快照保存模型名称、温度和结构化生成参数，不保存 API Key。

### 4.2 选题与脚本

文案页面提供两种入口：

- AI 选题：结合 Persona 一次生成 5 个互不重复的选题，支持“换一批”。
- 自定义文案：用户直接粘贴或输入完整口播稿。

选题确认后生成 200–1000 字口播稿。脚本保持短句、口语化、强开场、明确价值和克制 CTA，适配抖音、小红书口播语境。

### 4.3 本地脚本参考库

用户后续可以导入优秀脚本。系统保存脚本来源和标签，并提取开场钩子、叙事结构、行业、语气与 CTA。生成时检索最相关的少量结构示例加入 Prompt，不直接复制原文，也不要求训练或微调模型。

### 4.4 违禁词检查

检查分两层执行：

1. 本地规则库标记广告法和平台常见高风险表达，如“最”“第一”“国家级”等。
2. AI 结合上下文解释风险并给出替换建议。

替换必须由用户确认。界面显示原词、风险类型、原因和建议文本。规则库标明“风险提示，不构成法律结论”，并允许更新。

## 5. 音频制作

音频制作是独立页面，不混入文案页或镜头页。

### 5.1 音色来源

- MiniMax 系统音色列表。
- MiniMax 已有自定义音色 ID。
- 上传声音样本并调用 MiniMax 真实声音克隆接口。

上传前检查格式、文件大小、时长、可读性和基础音量。克隆状态持久化，支持处理中、成功、失败和重新提交。接口或账号权限错误转换为中文提示。

### 5.2 配音参数

- 情感。
- 语速。
- 音量。
- 音调。
- MiniMax 支持的语言增强参数。

情感列表以 MiniMax 当前模型支持的枚举为准；不支持的组合在提交前阻止。

### 5.3 试听和生成

- 音色试听使用固定短文本。
- 配音预览使用当前文案片段。
- 完整生成按文案分段逐段执行。
- 每段音频保存缓存键、文件路径、真实时长和状态。
- 单段失败可独立重试；修改文本或参数后仅使受影响的音频缓存失效。

## 6. 镜头剪辑

“镜头模板”更名为“镜头剪辑”，同时保留可复用模板管理能力。

### 6.1 文案与镜头

页面读取已确认文案和逐段音频。系统根据语义、标点和音频时长生成初始镜头：

- 每段口播至少对应一个镜头。
- 用户可拆分、合并、增删和排序。
- 镜头默认跟随对应音频时长。
- 用户可以设置固定或自动时长。
- 修改镜头文案后，对应音频标记为需要重新生成。

### 6.2 素材映射

每个镜头选择一个素材中心分类。生成时只从对应分类挑选可读素材，并沿用现有随机种子、相邻去重和历史去重机制。

素材不足时按以下顺序降级：

1. 换用同分类其他素材。
2. 同一素材使用不同时间区间。
3. 在用户允许时循环短素材。
4. 明确失败并指出缺少的分类。

### 6.3 页面布局

桌面宽度下采用三栏：

- 左栏：模板选择、复制、导入导出和模板说明。
- 中栏：逐段镜头编辑，是页面主要操作区。
- 右栏：BGM、标题、字幕和成片参数。

窄窗口下右栏折叠到中栏下方，核心镜头编辑不得被遮挡。

## 7. BGM、标题与字幕

### 7.1 背景音乐

BGM 支持：

- 单个音频文件。
- 本地音乐文件夹。
- 固定、随机、顺序三种选曲模式。
- MP3、WAV、M4A、AAC、FLAC。
- 音量、循环、淡入和淡出。

随机模式使用任务种子，保证任务重试时选曲一致。文件夹扫描结果缓存，损坏音频被隔离并显示中文原因。

### 7.2 标题和字幕

标题和字幕分别保存样式，支持：

- 系统字体选择。
- 导入本地 TTF、OTF 字体。
- 字号、字色、描边宽度、描边颜色。
- 阴影颜色、X/Y 偏移。
- 水平对齐和屏幕位置。
- 预设样式与实时手机画布预览。

FFmpeg 合成继续使用 ASS 字幕，并扩展样式生成器。任务快照保存字体文件引用和完整样式，缺失字体必须在编码前报错。

## 8. 品牌与视觉

整体视觉使用袋研官 VI：

- 主色：明黄。
- 主文本和主要操作：黑色。
- 内容背景：白色和浅暖灰。
- 成功、警告、错误保留可访问的语义颜色。

不复制参考软件的品牌、商标或专有素材，只借鉴清晰的大卡片、宽间距和阶段化操作方式。

用户提供的小羊头像替换当前 BAG LAB 字标，用于：

- 侧边栏品牌图标。
- 窗口图标。
- Windows 任务栏与桌面快捷方式图标。
- 安装包图标。

头像按居中圆角矩形裁切，保留足够安全边距，并输出 Windows ICO 所需尺寸。

## 9. 数据与接口边界

新增或扩展以下本地实体：

- `creation_drafts`：创作草稿及当前阶段。
- `copywriting_projects`：选题、文案、模型和检查结果。
- `reference_scripts`：优秀脚本与检索特征。
- `voice_profiles`：系统音色、自定义音色和克隆状态。
- `draft_audio_segments`：逐段音频及缓存信息。
- `template_settings`：BGM、标题、字幕和成片默认设置。

Python 服务新增：

- 生成选题。
- 生成完整文案。
- 检查并建议替换违禁词。
- 检索参考脚本。
- 提交和查询 MiniMax 声音克隆。
- 查询音色能力。
- 音色试听和逐段配音。
- 音频、音乐和字体探测。

Electron Renderer 仍不得直接访问 Node 或任意文件系统。文件、文件夹和字体选择全部经由白名单 Preload IPC。

## 10. 错误处理与恢复

- 所有用户可见错误转换成中文，并附带可执行的下一步。
- 网络请求设置超时、有限重试和取消能力。
- MiniMax 限流只重试当前克隆或音频片段。
- 文案结构化输出失败最多修复两次。
- 草稿写入采用事务，应用异常退出后恢复最后一次完整状态。
- 编码前检查素材、音频、BGM、字体、输出目录和磁盘空间。
- 日志继续脱敏 API Key、Authorization、Cookie、声音上传地址和个人字段。

## 11. 测试与验收

### 自动测试

- 草稿迁移、自动保存、恢复和快照不可变性。
- 模型切换、选题去重、字数限制和结构化输出修复。
- 违禁词规则、AI 建议和用户确认替换。
- 声音样本校验、克隆状态、试听、缓存和单段重试。
- 镜头拆分、合并、排序、音频时长同步和素材分类映射。
- BGM 文件夹扫描、FLAC 探测、随机种子和损坏文件隔离。
- ASS 字体、颜色、描边、阴影和位置命令快照。
- Electron 完整流程 E2E。

### 真实验收

1. 选择 Persona，通过百炼 DeepSeek 生成 5 个选题和一篇合格口播稿。
2. 完成违禁词检查并人工确认替换。
3. 上传用户声音样本，完成 MiniMax 声音克隆并试听。
4. 逐段生成配音，验证修改单段后只重新生成该段。
5. 从素材中心不同分类映射镜头。
6. 从包含 FLAC 的音乐文件夹按随机模式选择 BGM。
7. 使用导入字体和自定义字幕样式生成成片。
8. 重启应用后恢复草稿，创建任务并生成可播放视频。
9. 新安装包的窗口、任务栏、桌面和卸载列表均显示袋研官名称与小羊头像。

## 12. 分阶段交付

### 阶段一：创作基础与视觉

完成数据库迁移、草稿、侧边栏重排、黄黑白视觉、小羊头像、文案生成页面和镜头剪辑三栏编辑器。

### 阶段二：音频与样式

完成独立音频制作页、MiniMax 声音克隆、试听、情感参数、逐段音频、BGM 文件夹与 FLAC、标题字幕样式。

### 阶段三：完整链路

串联草稿、任务快照、FFmpeg 合成、失败恢复、完整 E2E 和 Windows 安装包验收。

每个阶段都必须通过当前范围的自动测试和安装版冒烟测试后再进入下一阶段。
